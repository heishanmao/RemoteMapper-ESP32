# Second USB audio stall on 1.2.31; 1.2.32 experiment and 1.2.33 rollback

The user observed Windows reporting an input-device switch and ending dictation. On first HTTP read, firmware 1.2.31 had uptime 63 seconds, so the one-shot audio watchdog had restarted the MCU before inspection. The BLE connection and HTTP server were healthy. Windows had not reopened capture after the device switch; `/api/audio` correctly showed alt 0 and zero audio completions on the new boot. The reboot preserved a first-audio-fault snapshot in NVS. Snapshots are in `.cache/incident-20260930-1231-repeat/`.

This fault differs from the previous masked-FIFO-empty snapshot. UAC IN3 had an enabled endpoint (`DIEPCTL=0x80c48040`), a pending 64-byte transfer (`DIEPTSIZ=0x80040`), the FIFO-empty mask **set** (`DTKNQR4_FIFOEMPTYMSK=0x8`), `DIEPINT=0x2010` with TXFE **not asserted**, and 35 FIFO words free. The last completion was 5.648 seconds before the saved snapshot. The 1.2.31 narrow re-arm cannot address this state, so a single lost mask update is not a complete root-cause explanation.

After reboot, a Windows WinMM test opened the microphone 10 times and captured 41–44 KB per cycle, with no new recovery or failed audio submission. This confirms the restart restored USB transport, while the Windows dictation session stopped because USB re-enumeration changed the capture device.

As a controlled experiment, 1.2.32 changed USB isochronous transfer from 64 bytes every 2 ms to 32 bytes every 1 ms. The driver has an explicit odd/even-frame branch for interval 1, so this was a plausible scheduling test. It compiled and booted, and WinMM could open capture, but only about 19–25 KB reached Windows per 1.2-second cycle (roughly half the expected 38.4 KB). This experiment **failed throughput validation** and was immediately reverted. Version 1.2.33 restores the prior 64-byte/2-ms endpoint and pump, retaining the 1.2.31 targeted re-arm and one-shot fault capture. After a transient WinMM open error during Windows re-enumeration, the same 10-cycle capture test passed at roughly 39–47 KB per cycle with no USB recovery.

The user still needs to test physical voice press/release on 1.2.33. Neither the short transport test nor the snapshots establish a complete fix for the intermittent endpoint stall. Further work should instrument the first failed transfer and host service state without treating every audio silence as a DCD mask race.
