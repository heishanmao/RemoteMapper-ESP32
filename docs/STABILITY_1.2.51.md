# 1.2.51 稳定性修补

本轮以 1.2.50 的 USB DWC2 / HID 完成保护为基础，收紧语音会话和配置切换的并发边界。验证结果与固件、源码快照一起记录在发布包的 `validation.json`，不能把主机测试视作真实遥控器与输入法的完整验证。

## 语音与按键

- HID 超时判定携带 registry generation，取得引擎锁后再次确认；新一轮按键使旧判定失效。音频接收超时提交给 NimBLE host，与收包串行处理，并再次验证最近音频帧时间。
- 强制释放、配置替换与物理按键共用引擎同步边界。旧按键清理完成后才允许新按键进入。
- 强制清理取消未完成的点击、双击、长按和重复状态，只释放已经实际发出的保持动作，避免清理时派生一次点击或 Wake-on-LAN。
- BLE 麦克风命令由 NimBLE host 串行执行。强制关闭携带原会话 epoch，不能关闭后续的新会话；不持引擎锁执行 GATT 写入。
- 沿用已验证的 ATVV 命令格式；遥控器 STOP 通知缺少已确认的会话标识，仍按当前会话处理。该协议限制意味着不能保证识别远端晚到的旧 STOP，本轮保证的是本地延迟清理不关闭新会话。
- 设备仍采用按住说话，遥控器自身的 60 秒限制保持不变，本地物理会话保护上限为 62 秒。

## 配置、日志与升级

- JSON 先完整解析为候选配置，验证类型、范围、层编号、重复物理键和 MAC；持久化成功且读回一致后才替换运行映射。
- 配置导入先验证所有部分。Wi-Fi 写入先暂存，按键保存失败时尝试回滚 Wi-Fi，失败信息明确说明结果。NVS 没有跨命名空间的断电原子事务，这一限制仍存在。
- UART 与 CDC 各自使用有界输出队列；一条通道停读不会阻挡另一条。CLI `help` 整体排队，拥塞时拒绝完整回复。
- OTA 镜像验证通过后先写入并验证安全启动标记，再激活分区。旧镜像不能清除下次启动的标记；确认与回滚的 NVS 失败不虚报成功，确认最多重试 3 次、间隔 5 秒。
- 普通 OTA 状态查询不再重新校验整个目标镜像；`/api/ota/status?verify=1` 可显式执行诊断。上传最终校验保持开启。

## 可复现构建与耗时诊断

锁定已经使用的 PlatformIO 7.1.3、Arduino ESP32 2.0.17 包、NimBLE 1.4.3 和 ArduinoJson 7.4.3。本轮没有合并上游功能或迁移大版本。所需 SDK 补丁遇到未知源码时直接中止构建，全部校验通过后才写入。

N16R8 明确引用 `partitions/remotemapper_n16r8.csv`，避免仓库与 SDK 的同名 `default_16MB.csv` 内容不同。分区表保持已部署布局：NVS 为 `0x9000/0x5000`，OTA 数据为 `0xe000/0x2000`，应用为 `0x10000` 和 `0x650000`；本轮不迁移分区。

`/api/status.runtime.stages` 分别记录 USB、Wi-Fi、Web、CLI、维护和日志处理的调用数、最近/最大耗时、最大值时间和超过 50 ms 的次数。这是包含抢占和等待的墙钟时间，不能当成 CPU 占用率或自动重启依据。

统一主机验证入口：

```powershell
.\.venv\Scripts\python.exe tools\run_host_tests.py
```

可设置 `REMOTEMAPPER_HOST_CXX_JSON` 为主机编译器参数数组。默认缺少运行测试的编译器会使验证失败；只有明确使用 `--allow-runtime-skips` 才允许部分检查。`--log` 可保存完整结果。

## 验证边界

发布前执行生产代码主机回归、默认/USB 测试配置构建及符号检查。OTA 后检查版本、启动任务、USB、蓝牙、安全启动确认，并反复开关 Windows 麦克风，与空 HID 报告并发测试。

这种 USB 压测不发送 Alt，不保存采集音频，也不能替代遥控器 BLE 开麦与输入法识别。日常使用出现问题时保留故障现场，对照会话 epoch、HID 完成、USB 计数及阶段耗时排查。
