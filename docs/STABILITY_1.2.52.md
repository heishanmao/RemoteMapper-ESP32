# 1.2.52 Wi-Fi 配置保存可靠性

本轮继续在自己的开发分支完善配置持久化。语音输入方式沿用 1.2.51，遥控器自身仍有 60 秒上限。

## 修补范围

- 普通 Wi-Fi、热点、策略与空闲休眠设置检查 NVS 写入和读回结果，成功后才更新运行状态或重新配置网络。
- 读取明确区分缺键与 NVS 错误，避免用默认值覆盖旧配置。空字符串保存检查真实提交状态和键的读回，避开 SDK 中成功与失败都可能返回 `0` 的歧义。运行态的值相同也不能替代持久化验证。
- STA 的 SSID 与密码作为一组保存，局部失败时尝试恢复原存储值，回滚失败需明确记录。
- 电源设置先校验完整请求，所有候选设置保存成功后再发布运行状态，避免非法或失败请求只改了一半。
- Web 接口区分输入格式错误与保存失败：前者返回 HTTP 400，后者返回 HTTP 500。
- NVS 初始化失败保留诊断信息，后续保存不能虚报成功。

## 验证与边界

两种 N16R8 配置均构建通过，61 项主机检查与 4 个补充算法模型通过，无跳过。故障注入直接执行生产 Wi-Fi 保存路径，覆盖写失败、读回不一致、空密码提交失败、部分写入与回滚失败，以及保存失败后运行状态和网络调用不变。发布包保存完整构建、主机测试和设备验证记录。

设备已通过 13 项非法请求拒绝检查与 1 项同值有效保存检查，电源设置未被非法请求改变。OTA 后完成 10 次 Windows 麦克风开关及 4021 个空 HID 报告回归，没有新增 HID 超时、USB 恢复或重启；音频数据不保存。上一版的 100 次压测是独立历史记录，不计入本版测试次数。

这些回滚处理不构成跨字段断电原子事务；设备在写入期间突然断电仍可能留下部分更新。串口刷机脚本与上一版保持同一分区地址，本轮采用 OTA 部署，串口物理刷写不作为本轮验证结果。

真实遥控器与输入法的长期识别、60 秒结束后再次录音、蓝牙断连恢复仍需实际使用验证。管理鉴权、发布流程、大版本迁移和进一步模块拆分留待后续独立处理。
