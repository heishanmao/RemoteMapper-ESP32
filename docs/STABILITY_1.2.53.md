# 1.2.53 语音启动与修饰键释放

本轮针对“开麦失败却已输出右 Alt”和语音动作遗漏释放修补。正常连接后的语音键继续按下立即响应，遥控器自身的 60 秒结束机制保持有效。

## 修补内容

- 只有当前蓝牙连接握手完成、命令通道可用，并收到支持 16 kHz 的能力响应，才接受语音保持动作。准备期间的按下不会创建本地音频会话、发送 Alt 或打开远端麦克风；能力晚到不会重放这次动作，需要松手后重新按下。普通按键映射照常处理。
- 开麦命令写入失败时，仅撤销仍属于当前会话的音频、语音 HID、保护登记和指示灯；旧会话的失败结果不能撤销新会话。连接能力发布与按键事务串行，断连清理也撤销已接受的语音动作。
- 按键通知先于 ATVV AUDIO_START 时，后者准备解码器会暂时关闭音频管线；重复按下在按键状态机中不会重新输出保持动作。现在会重新激活已接受会话的音频管线，同时保持只有一次 HID 按下。
- 自定义长按动作设为 VOICE_HOLD 后，松手补发 VOICE_RELEASE。已经松手才判定出的单击或双击语音动作改为有界键盘 tap，避免创建没有后续物理释放的保持动作。默认语音键无需等待长按判定。
- `/api/guard` 的 `hid_diagnostics.keyboard_reports` 新增最近 32 条键盘发送尝试的完整报告、命令编号与队列代次、来源和完成结果。固定 RAM 缓冲合并相同重试，不在发送路径写 NVS、分配内存或输出日志。`completed=false` 表示没有确认完成，不能据此认定主机没有接收。

## 验证

63 项主机检查和 4 个补充模型通过，无跳过。新增回归执行生产按键状态机、语音门控和实际音频管线，覆盖未就绪拒绝、能力晚到不重放、正常按下释放、失效后的释放决策，以及按键与音频通知两种先后次序。实际状态机回归也覆盖长按松手、延迟单击与真正双击的语音动作。报告缓冲测试覆盖完整字节复制、失败与成功保留、重复压缩和环形覆盖。

两种 N16R8 配置构建通过。默认配置静态 RAM 125124 字节、程序 1468485 字节；USB 测试别名静态 RAM 相同、程序 1468613 字节。分区镜像与 1.2.52 完全相同。

本轮通过 OTA 部署，实际设备已返回版本 1.2.53，蓝牙与 USB 初始化正常、修饰键为零、无待发送键盘或消费者报告。启动阶段仍观察到一次 HID 完成超时；新增内容记录证明该次报告为全零释放，后续全零释放成功。没有把这个历史启动现象计为语音故障已解决的证明。

运行超过 120 秒后，新固件安全启动确认已完成：`rollback_armed=false`、`boot_fail_count=0`，期间没有新增 HID 超时或 USB 恢复。

## 边界

这轮修复了已证实的固件缺陷，不能据此宣布 Windows 两侧 Ctrl 持续失效的根因已经确定。原始故障前日志已被用户拔插重启覆盖；仍需真实遥控器与输入法连续使用验证。

普通遥控动作仍使用单个完整键盘报告，语音与其他按键的并发组合语义本轮未重构。管理界面、Wi-Fi 配置和 Codex 按键映射没有改动。串口刷机文件已保存，未进行物理串口刷写验证。
