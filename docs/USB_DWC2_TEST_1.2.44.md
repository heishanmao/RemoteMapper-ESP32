# USB audio controller trial (1.2.44-usbtest3)

The 1.2.43 incident left EP3 IN enabled with a 64-byte transfer pending and `INCOMPISOIN` set. The bundled TinyUSB 0.16 `dcd_esp32sx` controller driver has no per-endpoint close function. Our UAC alternate-setting handler therefore kept the endpoint open across host capture close/open, leaving a plausible stale-transfer path.

This trial keeps the existing Arduino/TinyUSB 0.16 device stack and replaces only its controller driver with the same TinyUSB release's ESP32-S3 DWC2 driver (source tag `0.16.0`, commit `1eb6ce784ca9b8acbbe43dba9f1d9c26c2e80eb0`). The upstream MIT header is retained in the vendored files. It is opt-in through `pio run -e esp32s3_n16r8_usb_test`; the normal N16R8 build still links the bundled driver and reports 1.2.43. The test build reports `1.2.44-usbtest3`.

On the test build, UAC alt 0 closes its ISO IN endpoint, cancels TinyUSB's busy/claim state through `usbd_edpt_close`, and frees the last-allocated FIFO. Alt 1 opens the endpoint again. The controller close wait is limited to 2 ms at each IN disable phase; a timeout requests the existing full USB recovery instead of hanging the USB task. The test driver also sets ISO frame parity before enabling a transfer for the microphone's `bInterval=2`. Its UAC packet submission is paced by the 2 ms task, because immediate resubmission after each completion produced about 800-1000 packets/s and Windows consumed the 64 KB test buffer too quickly.

Validation on Windows, firmware `1.2.44-usbtest3`: CDC enumerated, BLE reconnected, HTTP status loaded, and the WinMM capture script completed 100 consecutive open/capture/close cycles without a failed submission or USB recovery. Each active capture delivered roughly 39-45 KB in 1.2-1.4 seconds, about 470-500 completed 64-byte packets/s. A subsequent three-cycle run with explicit byte-rate and packet-rate assertions passed. WinMM must run with normal Windows microphone access; the sandboxed process returned error 1 for both RemoteMapper and a separate Redmi microphone, so sandbox results are not USB evidence.

The user then completed nearly 30 Chatterfly voice-key cycles without a visible failure. Device logs show sequence numbers through 29, BLE audio frames and nonzero USB PCM in the recent speaking sessions, and a completed HID keyboard release after each. The post-test guard reported no held key or pending keyboard report. Uptime was 1,074 seconds with zero USB recoveries and zero UAC transfer failures. Two HID transmit failures in the cumulative counter were from startup before the USB host was ready; the count did not increase during the physical test.

This is an initial regression result, not proof of the multi-hour fault being eliminated. The old 1.2.43 image and ELF are saved under `.cache/firmware-1.2.43-before-dwc2/` for rollback. Wi-Fi idle timeout was temporarily disabled through CLI for OTA and testing, then restored to its original enabled, two-minute on-demand setting after the physical test.
